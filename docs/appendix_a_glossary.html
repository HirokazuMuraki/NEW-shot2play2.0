Appendix A — Glossary

This appendix defines the principal terms used throughout the NEW-shot2play Protocol Suite Version 2.0.

The definitions in this appendix apply to the interpretation of the protocol architecture, protocol objects, state transitions, security requirements, conformance requirements, and use cases defined in this specification.

A.1 Authentication

Authentication is the process by which a subject establishes an authenticated identity or authenticated state using an applicable authentication mechanism.

Authentication establishes identity-related state but does not, by itself, establish authorization to perform a protected operation.

A.2 Credential

A Credential is information or cryptographic material used by an Authentication mechanism to establish or verify the authenticated state of a subject.

A.3 Identity

Identity is the protocol representation of the subject that is associated with an authenticated state and with applicable Entitlements, Policies, and Authorization Decisions.

A.4 Subject

A Subject is an entity for which Authentication, Entitlement, Policy Evaluation, or Authorization is performed.

A.5 Session

A Session is a protocol or Service context within which authenticated and, where applicable, authorization state may remain associated with a subject across one or more operations.

A.6 Entitlement

An Entitlement is an authorization basis associated with a subject that defines or contributes to the conditions under which access to a Service, resource, operation, transaction, or other protected object may be permitted.

An Entitlement does not necessarily constitute an unconditional authorization to execute an operation.

A.7 Entitlement Scope

Entitlement Scope is the set of Services, resources, operations, transactions, or other targets to which an Entitlement applies.

A.8 Entitlement State

Entitlement State is the current protocol state associated with an Entitlement, including its applicability, validity, expiration, usage, revocation, and other Policy-defined conditions.

A.9 Policy

A Policy is a set of rules and conditions used to determine the applicability of an Entitlement and the conditions under which an Authorization Decision may be established or enforced.

A.10 Policy Evaluation

Policy Evaluation is the process of evaluating applicable Policies against the current authorization context to determine whether the conditions required for authorization are satisfied.

A.11 Policy Evaluation Result

Policy Evaluation Result is the result produced by Policy Evaluation indicating whether the applicable Policy conditions are satisfied and identifying any Policy-defined conditions applicable to subsequent protocol processing.

A.12 Policy Version

Policy Version identifies the specific version of a Policy under which an Entitlement or Authorization Decision was evaluated.

A.13 Authorization

Authorization is the protocol process by which the system determines whether a subject is permitted to perform a specified operation against a specified Service, resource, transaction, or other protected target.

A.14 Authorization Decision

An Authorization Decision is the effective result of the Authorization process for a particular authorization request and context.

An Authorization Decision MAY permit or deny the requested operation and MAY include scope, validity, binding, or other Policy-defined conditions.

A.15 Authorization State

Authorization State is the protocol state representing the current authorization condition applicable to a subject, Entitlement, Service, resource, transaction, or operation.

A.16 Authorization Context

Authorization Context is the collection of identity, Entitlement, Policy, transaction, Service, resource, temporal, and other contextual information required to evaluate or enforce an Authorization Decision.

A.17 Authorization Scope

Authorization Scope is the set of operations, resources, Services, transactions, or other targets for which an Authorization Decision is effective.

A.18 Decision Binding

Decision Binding is the association of an Authorization Decision with the subject, Entitlement, Policy, Service, operation, resource, transaction, or other context on which the decision depends.

A.19 Security Context

Security Context is the collection of security-relevant state and references required by a protocol component to evaluate or enforce a security condition.

Security Context MAY include authentication state, integrity state, freshness information, validity information, revocation or invalidation state, and other security-relevant information required by the applicable protocol layer.

A.20 Service

A Service is a protected application, system function, resource provider, or other execution boundary to which the protocol applies an Authorization Decision.

A.21 Service Enforcement

Service Enforcement is the application of an effective Authorization Decision at the boundary of a protected Service before execution of the requested operation.

A.22 Transaction

A Transaction is a defined interaction or operation whose state MAY be used as part of an Entitlement, Policy Evaluation, Authorization Decision, or Service Enforcement process.

A.23 Effective Time

Effective Time is the time from which an Entitlement, Authorization Decision, or other time-dependent protocol object is permitted to become effective.

A.24 Validity

Validity is the condition under which an Entitlement, Authorization Decision, or other time- or state-dependent protocol object remains applicable for the purpose for which it was established.

A.25 Expiration

Expiration is the condition under which an Entitlement, Authorization Decision, or other time-dependent protocol object ceases to be effective because its defined validity period has ended.

A.26 Freshness

Freshness is the property indicating that protocol state or security-relevant information is sufficiently recent for the applicable Policy or security requirement.

Freshness is distinct from Validity and does not by itself establish that an Entitlement or Authorization Decision remains valid.

A.27 Revocation

Revocation is the explicit invalidation of an Entitlement, Authorization Decision, or other authorization basis before its previously defined expiration.

A.28 Invalidation

Invalidation is the protocol state transition or mechanism by which previously established protocol state is made no longer applicable for subsequent processing or enforcement.

A.29 Usage Count

Usage Count is the number of permitted or consumed uses associated with an Entitlement or other Policy-controlled authorization condition.

A.30 Cross-Service Authorization

Cross-Service Authorization is authorization in which an Entitlement, authorization context, or other authorization state established in relation to one Service is used by another Service in accordance with applicable Policy.

A.31 Authorization State Reconstruction

Authorization State Reconstruction is the process of restoring or deriving authorization state from authoritative or trusted protocol state after a restart, failover, state loss, or other interruption.

A.32 Authorization Decision Caching

Authorization Decision Caching is the temporary retention of an Authorization Decision for subsequent use without repeating the complete authorization evaluation, subject to its validity, scope, revocation, and Policy requirements.

A.33 Fail-Closed

Fail-Closed is the security behavior in which a protected operation is denied when the system cannot establish sufficient valid authorization state to permit execution.

A.34 Protected Operation

A Protected Operation is an operation whose execution is subject to an Authorization Decision and Service Enforcement.

A.35 Authorization Request

An Authorization Request is a request to determine whether a specified subject is permitted to perform a specified operation against a specified Service, resource, transaction, or other protected target.

A.36 Authorization State Continuity

Authorization State Continuity is the preservation of the semantic validity of authorization state while the subject or request progresses through permitted protocol or Service transitions.

A.37 Normative Requirement

A Normative Requirement is a mandatory requirement expressed by this specification using terms such as MUST or MUST NOT.

A.38 Conforming Implementation

A Conforming Implementation is an implementation that satisfies all mandatory requirements applicable to the protocol behavior, objects, state transitions, security controls, and Service Enforcement defined by this specification.

A.39 Conformance Class

Conformance Class is a defined category of conformance requirements identifying the mandatory protocol behavior that a conforming implementation is required to support.

A.40 Layer Conformance

Layer Conformance is conformance to the mandatory requirements applicable to a particular protocol layer, including the requirements governing its inputs, outputs, state transitions, and interactions with adjacent protocol layers.
